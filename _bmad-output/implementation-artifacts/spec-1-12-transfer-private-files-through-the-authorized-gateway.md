## Intent

**Problem:** There is no way to move a private file in or out. No user file may cross a Vercel function (4.5 MB cap), no storage credential or reusable signed URL may reach a browser, and access must stop mid-transfer when it is revoked; none of the contracts later stories reuse (service-signing keys, tickets, staging leases, manifests, signed delete commands) exists.

**Approach:** Build `workers/files`, a Node HTTP gateway run on Railway, authorized by application-signed single-use Ed25519 tickets and by a live Postgres read before every chunk of at most 1 MiB, with its own database role and its own Storage key. Add the service-signing contract, a ticket route in the app, the Artifacts-owned database records, signed delete commands and an hourly staging cleanup on the Story 1.9 scheduler. Nothing is run against a hosted service from here; the gateway runs locally against the Supabase CLI stack.

None is required of a hosted app (the ticket route and the cleanup task fail closed when unset), and `SERVICE_SIGNING_KEY_*` joins the preview-forbidden names. **Key contract** (`lib/service-signing.ts`, imports only `node:crypto`, so the worker can import it): issuers are `application`, `gateway`, `cad-worker`, `engine-worker`, `backup-service`, `heartbeat` (only `application` issues anything here). A key set is JSON `{issuer, active: kid, retiring: {kid, until} | null, keys: {kid: base64 SPKI Ed25519 public key}}`: at most one retiring key, `until` required with it, every named kid present in `keys`, nothing else; the private key (`SERVICE_SIGNING_KEY_<ISSUER>`) is base64 PKCS#8 of the active kid and is checked to match its public half. A token is `base64url(header {v:1, alg:"EdDSA", kid}).base64url(payload).base64url(signature)` over the label `nova3d/service-token/v1\0` plus the first two parts; the payload holds `iss, aud, env (INSTANCE_ID), jti (128-bit random), iat, exp, typ` and its type's claims. Verification, in this order, with one uniform refusal that names no reason: size cap; shape; issuer and audience; environment; kid is the active key or the retiring key before its `until`; not revoked (a revoked kid is refused everywhere at once); signature; `exp - iat` at most 300 s; `iat` at most 60 s in the future; now not after `exp`. Revocation is a row in `artifacts.service_key_revocations`; `api.revoke_service_key(issuer, kid, reason)` writes it and, in the same transaction, ends every staging lease and transfer handle opened under that kid. **Tickets** (`typ:"ticket"`, `iss:"application"`, `aud:"gateway"`): claims `acct, sid (session grant), epoch, dir (upload|download), tk (target kind), tid (target id)` and, for an upload, `cls (picture|file), len, sha (hex SHA-256), ct`; no storage credential, no URL, nothing reusable. `POST /api/transfers/tickets` (private, first statement `requireMutationAccess`, `force-dynamic`, `no-store`, body of at most 4 KiB, 503 when the keys or `FILE_GATEWAY_URL` are unset) signs a ticket valid for 5 minutes (the default and the maximum) for the verified Account, session grant and epoch and answers `{ticket, gateway}`; a target kind with no resolver is refused (400) there and again at the gateway. **Database** (migration `20261015120000_file_gateway.sql`): a new schema `artifacts` (not exposed by the Data API) owns `staging_leases`, `ticket_redemptions`, `transfer_handles`, `manifests`, `attachment_transforms` and `service_key_revocations`, each closed (RLS on, no policy, every privilege revoked from public, anon, authenticated and service_role) with default-privilege revokes for the schema; a role `nova3d_gateway` (login, no password in any migration; the local password is set by `seed.sql`, the hosted one by hand) holds usage on `artifacts`, select on the authorization views `artifacts.session_authority` and `artifacts.instance`, insert and select on `ticket_redemptions` and `transfer_handles`, insert and select on `staging_leases` with update on only its progress columns (`received_length`, `state`, `expires_at`), and execute on `artifacts.publish_attachment`: nothing else, no `api`, `identity`, `projects` or `lifecycle` object. `session_authority` answers one row per session with the same liveness `api.authorize_session` answers (revoked, expired at 30 days, idle at 7, stale epoch, disabled, no Auth session, subject mismatch, tombstoned Account) and a test proves the two agree over every state; it never writes. A ticket is redeemed by inserting its `jti` (primary key, so a replay fails) with Account, session, direction, target, kid and expiry. A transfer handle (32 random bytes; only its SHA-256 is stored) binds session grant, Account, target, direction, kid and an expiry of at most 30 minutes; it is created for every redeemed ticket and stays internal unless the browser-native path hands it out. The private bucket `private-files` (private; created by the migration through `storage.buckets`) holds `staging/<account>/<upload>` and `objects/<account>/<root>`; user-data buckets are never public. `api.preflight` is re-created carrying every earlier probe plus the new ones. **Gateway** (`workers/files/src`, plain `node:http`, TypeScript run by Node's type stripping, imports only relative `.ts` files, `lib/service-signing.ts` and `lib/canonical-json.ts`): it verifies `INSTANCE_ID`/`APP_ENV` against `artifacts.instance` at startup and exits non-zero on a mismatch or missing configuration; it holds no cookie and sets none; every response is `Cache-Control: no-store` with `X-Content-Type-Options: nosniff`; it logs no ticket, handle, URL, key or body; cross-origin calls are answered only for `APP_ORIGIN` (one allowed origin, `Vary: Origin`, no wildcard, no credentials) and any other `Origin` is 403. Routes: `GET /healthz`; `PUT /v1/uploads/<id>` (ticket in `Authorization: Ticket <token>`; `Content-Length`, `Content-Type` and `X-Content-SHA256` must equal the ticket's `len`, `ct`, `sha`; picture uploads are JPEG, PNG or WebP verified by their leading bytes and at most 12 MiB, other files `application/octet-stream` at most 100 MiB; the Account's open staging is at most 250 MiB); `GET /v1/files/<kind>/<id>` with one `Range` at most; `GET /d/<ticket>` answering 303 to `/h/<handle>/<target id>`; `GET /h/<handle>/<target id>` (a bearer capability tied to the session grant, at most 30 minutes, `Referrer-Policy: no-referrer`, ranges and the browser's own resume, a different target id is refused); `POST /v1/commands`. A redeemed ticket opens one transfer and nothing else: resuming or reading another range needs a new ticket, and an interrupted upload restarts. Before every chunk of at most 1 MiB, in both directions, it reads `session_authority` and the target's state through its resolver in Postgres, never caches the answer, and stops the transfer when the answer is not `allowed` or the database does not answer (503 before bytes, a closed stream after; bytes already delivered are not recalled). Uploads stream into S3 (multipart, its own key pair), compute SHA-256 while streaming, and enforce checksum, content type, size, ownership and quota before the lease becomes `complete`; a failed upload deletes its partial object and releases its lease. A lease lasts 24 hours and activity renews it. The resolver registry maps a target kind to a function that reads one Postgres authorization view; this story registers `staging` (a lease of the same Account, not expired, not released), and a test-only fixture resolver lives under `tests/support`; a kind with no resolver is refused. The attach step is `POST /v1/commands` with `cmd:"attach"` (upload id, registered transform name): the gateway copies the verified object to `objects/<account>/<sha256>`, builds the manifest body `{id, scope (account), activity, kind, digest, length, serialization:1, children:[]}`, serializes it with RFC 8785 (`lib/canonical-json.ts`, written here, with the RFC's own vectors), and calls `artifacts.publish_attachment`, which checks the lease is `complete` and the Account's own, the transform is registered (`attachment_transforms` holds `none` only; Story 2.12 registers the metadata strip), that `root` equals the SHA-256 of the body, and inserts the immutable manifest and marks the lease `attached`, once (a repeat returns the same manifest). **Commands** (`typ:"command"`, `iss:"application"`, `aud:"gateway"`, claims `cmd` and its fields, valid 5 minutes, single use through the same redemption record, a request with an `Origin` header refused): `attach`, `delete-staging` (an upload id and Account: the gateway re-checks in one statement that the lease is expired or released, then deletes that exact prefix) and `delete-root` (an Account and root: the gateway deletes `objects/<account>/<root>`); every key is built from validated hex or UUID parts, never from caller text, and only the gateway deletes Storage objects. **Cleanup:** `staging-cleanup` joins `lib/schedules.ts` (hourly, `0 * * * *`) and `lib/job-tasks.ts`: `api.list_expired_staging(limit)` (service role, at most 50) names expired leases, `lib/gateway-client.ts` sends one signed `delete-staging` each, and the task records counts only; with no gateway configured the run is `no_store`. The gateway client sets a timeout, `redirect:'error'` and `no-store`. **Worker image:** `workers/files/Dockerfile` builds from the repository root (the context of `.github/workflows/workers.yml` changes from `workers/<name>` to `.` with `-f workers/<name>/Dockerfile`, and `.dockerignore` keeps the context small), copies only the lockfile, `lib/service-signing.ts`, `lib/canonical-json.ts` and `workers/files`, installs with `npm ci --omit=dev`, runs as a non-root user and listens on `PORT`. **Docs and ledger:** `docs/authority-contract.md` gains "The file gateway"; `docs/staging.md` the migration row and a gateway section; `docs/secrets.md` the new names; `provisioning/ledger.json` gains `gateway-database-role`, `gateway-storage-s3-key`, `railway-files-service` and `hosted-gateway-check`; `docs/provisioning.md` is re-rendered.

**Acceptance Criteria:**
- Given an authenticated upload within and beyond the quota and size limits, when the gateway receives it, then checksum, content type, ownership and quota are enforced before anything is attached, a foreign upload ID is rejected, and the file never passes through a Vercel function.
- Given a large owned file, when a download or range transfer runs, then each range and each chunk of at most 1 MiB checks live session, Account and target state, no reusable signed storage URL is exposed and responses are no-store.
- Given disable, deletion, grant revocation or an unreachable database during a transfer, when the next chunk is authorized, then future chunks stop without cached authorization and delivered bytes are not claimed recalled.
- Given a ticket that is expired, replayed, bound to another Account, session, target or direction, or signed with a revoked key, when it is presented, then the gateway rejects it; a ticket under the one retiring key is accepted only for its outstanding window and a compromise revocation rejects it at once.
- Given an interrupted upload or abandoned staging, when its lease expires, then cleanup removes only expired staging and observes active leases.
- Given a transfer handle URL, when it is used after its session grant is revoked, after 30 minutes, or for another target, then the gateway refuses it, and within its lifetime it serves ranges and a browser resume for its own target.
- Given a signed delete command from the application and one from any other source, when the gateway receives them, then only the application-signed command deletes.

## Spec Change Log

## Design Notes

The gateway reaches Postgres directly under its own role and never holds the service-role key, so it cannot call `lib/authority.ts` or `api.*`: the authorization views and `artifacts` functions are the SQL twin of the application's guards, and a test keeps `session_authority` equal to `api.authorize_session`. Hosted, the gateway connects through the Supabase pooler in transaction mode (no session state, no named prepared statements); local and CI have no pooler, so tests use the direct connection and the hosted path is a `hosted-gateway-check`.

Epic text says Story 1.7 registers the Project resolver while earlier notes say this story does. There is no file that belongs to a Project yet, so this story registers `staging` only, a kind with no resolver is refused, and the Project resolver arrives with the first story that attaches files to a Project (the registry and the `artifacts` authorization views are the extension point).

Tickets and commands share one token format and one redemption record. A ticket authorizes opening one transfer; the transfer handle is what the gateway checks per chunk, so revoking a grant or a key needs no list of live streams. Retrying the same request after a lost response needs a new ticket by design.

```
Authorization: Ticket eyJ2IjoxLC…  (header.payload.signature, Ed25519)
payload = {"iss":"application","aud":"gateway","env":"<INSTANCE_ID>","jti":"…","iat":1,"exp":301,
           "typ":"ticket","acct":"…","sid":"…","epoch":3,"dir":"upload","tk":"staging","tid":"…",
           "cls":"picture","len":1048576,"sha":"<hex>","ct":"image/png"}
```
