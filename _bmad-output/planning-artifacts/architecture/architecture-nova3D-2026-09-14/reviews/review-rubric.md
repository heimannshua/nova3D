# Reviewer Gate — Architecture Spine

Verdict: **PASS WITH ACTIONS**. The spine is broad enough for the stated implementation scope, binds the major cross-feature invariants, includes deployment and operations, and makes the unbuilt generation, paid, offline, and deletion capabilities explicit gates. The gates are generally honest. Before implementation begins, resolve the following enforceability gaps; they are small enough to address without changing the architecture paradigm.

## Actionable defects

1. **Preview-to-production isolation is stated but not mechanically bound.** AD-19 says preview environments use synthetic data and disabled paid adapters, while G-6/G-9 depend on provider and data isolation. There is no deployment-time invariant preventing a preview from receiving production queue endpoints, storage credentials, callback secrets, or a live provider adapter. Add a required environment capability manifest and startup/CI checks: environment identity must match every Supabase/Storage/queue/provider resource; production-only secrets must be rejected in preview; paid adapters must fail closed unless the production environment claim is present. Path: `ARCHITECTURE-SPINE.md`, AD-19 and the G-6/G-9 gate rows.

2. **Worker and gateway authentication is named but not contractually specified enough to implement consistently.** The spine requires signed worker callbacks and a Railway gateway with live authorization, but does not bind signature algorithm/key rotation, clock/replay window, service identity, or the bounded-chunk authorization protocol. Independent builders could produce incompatible adapters while still claiming compliance. Add a versioned service-auth contract covering callback/gateway request fields, key IDs and rotation, replay/fencing checks, lease/stream chunk rechecks, and failure behavior; make it a prerequisite to G-1/G-9 and artifact-transfer implementation. Path: `ARCHITECTURE-SPINE.md`, Consistency Conventions → Network authority, AD-10, AD-13.

3. **The “zero automatic retries” job rule is not enforceable at the queue boundary.** AD-9 requires no automatic retries for failed research/generation, but Upstash Workflow/QStash transport redelivery remains possible and the spine does not define the durable distinction between transport redelivery, step timeout, provider uncertainty, and a terminal failed attempt. Add an explicit delivery policy and state machine: provider operation identity is persisted before dispatch, every redelivery is a reconcile-only path after an attempt receipt, and timeout/uncertain outcomes cannot be classified as failed-and-retried without reconciliation. Require this in the Jobs contract test gate. Path: `ARCHITECTURE-SPINE.md`, AD-9/AD-11 and “Implementation verification”.

4. **Schema/contract evolution is only partially bounded across TypeScript and Python.** The spine says the contracts package generates validators and uses expand/migrate/contract database rollout, but does not define compatibility windows, schema-version negotiation, or how an old queued Job selects a compatible worker. AD-19 says incompatible workers refuse a Job, yet no registry or refusal outcome is specified. Add a contract/worker compatibility matrix and migration rule (supported versions, minimum/maximum worker contract, explicit `incompatible_contract` terminal reason, retention window for old receipts). Path: `ARCHITECTURE-SPINE.md`, AD-19, Consistency Conventions, and G-1.

## Final disposition

The four findings are closed by the added Consistency Conventions: enforced environment identifiers and resource matching; signed service requests with audience, nonce, expiry, skew, key rotation and replay rules; bounded live-authorized artifact chunks; explicit queue retry/receipt reconciliation behavior; and a pinned Job contract/worker compatibility registry. No remaining rubric blockers found. Verdict: **PASS** (subject to the existing implementation gates G-1 through G-9).
