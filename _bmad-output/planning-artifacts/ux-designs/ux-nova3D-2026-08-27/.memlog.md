- (decision) Use Design Handoff mode targeting Claude Design; prepare a complete producer package now and leave actual mockup generation to the external tool
- (decision) Use all four confirmed inputs: final PRD and PRD addendum as authoritative, with product brief and brief addendum as supporting context
- (decision) The first screen is a simple home dashboard with three primary actions: My Projects, Create, and In Progress; In Progress groups model generations in progress and, when printer integration exists, prints in progress
- (decision) For first-version mockups, In Progress includes active model generation plus a Prints in Progress section clearly labelled Coming later; the UI must not imply printer control is already available
- (decision) Selecting Create opens a choice between Enter text and Upload picture as the two model-request entry paths
- (change) User requires Upload picture to work in the first version, overriding the finalized PRD deferral of picture workflows; this scope conflict must be reconciled before architecture
- (override) The first version includes both picture workflows: direct picture-to-3D conversion labelled image-derived and not historically verified, and research-assisted picture reconstruction that follows the evidence, Research Plan, and approval workflow
- (decision) Primary form factor is a browser-based computer experience supporting both desktop and laptop screens; core 3D inspection and evidence-review functionality must remain available across those sizes
- (change) First-version form factor expands to responsive desktop, laptop, and phone web experiences; this supersedes the PRD addendum assumption that desktop browser support could remain unresolved under AD-5
- (decision) Phone support is functionally complete rather than a reduced companion: Project creation, research review, 3D inspection, approvals, validation, and downloads must all work on phone as well as desktop and laptop
- (decision) Josh has no reference app or website whose appearance should guide nova3D; Claude Design should derive and present distinct original visual directions for Josh to choose before expanding to the complete mockup set
- (decision) Evidence views show original Hebrew source text alongside English translation and explanation; layouts must correctly support adjacent right-to-left Hebrew and left-to-right English content
- (change) The first-version UX must support internationalized interface and content in any configured language, including right-to-left layouts; original Source language, translation, and explanation remain visibly distinguishable
- (decision) On first use, nova3D automatically selects the supported interface language matching the Account holder device language
- (decision) Settings provides a manual interface-language selector that overrides automatic device-language detection and persists for the Account
- (decision) nova3D includes complete light and dark themes; evidence status, warnings, approval state, and 3D inspection remain equally legible in both
- (decision) The visual theme defaults to light mode on every device; users may manually switch to dark mode
- (decision) My Projects is model-focused: it presents the Account models, opening an item opens the model, and its supporting Sources are accessible directly from that model rather than requiring a separate research-area search
- (decision) Inside an open model, selecting a Model Feature reveals the Sources, interpretation, Detail Status, and decisions governing that exact part, with direct evidence-to-geometry and geometry-to-evidence navigation
- (decision) After text entry or picture upload and mode selection, nova3D presents its understood subject, scope, intended outcome, and Personalization and waits for explicit confirmation before research or generation begins
- (decision) Create sequencing separates scope from research settings: first the user confirms exactly what nova3D should generate; only afterward does a second step ask paid versus free research and cache reuse versus fresh research, before starting the Job
- (decision) During research, In Progress shows the actual Sources nova3D is examining and their current role, including lead versus accepted evidence; the interface displays recorded research activity and never fabricated hidden reasoning
- (decision) A user can open and read a Source from In Progress while the research Job continues independently; source inspection never pauses or interrupts background work
- (change) During active research or later Source inspection, the user can mark Do not use this Source; the Source is excluded from the Project evidence rather than merely hidden, and any affected Claims or decisions must be visibly reconsidered
- (decision) Rejecting a Source removes it from Project evidence, invalidates and visibly rechecks affected Claims and decisions, and lets the running research Job continue automatically while searching for replacement evidence
- (decision) nova3D sends phone push notifications when research, generation, validation, or printing finishes; selecting one opens the exact related Project item
- (decision) Do not use this Source is scoped only to the current Project and does not block or suppress that Source in other current or future Projects
- (decision) First-use onboarding explains each workflow stage in beginner-friendly language and can be dismissed once understood; guidance remains available for later reopening
- (change) Account Settings includes a Disabled Sources list for Sources the user does not want used across Projects; this account-wide control remains distinct from the current-Project-only Do not use this Source action
- (decision) Each Source in Settings uses a simple Account-wide on/off toggle: off prevents use, while on restores eligibility without deleting the Source record or its history
- (decision) Turning an Account-wide Source toggle off during an active research Job immediately excludes it from that Job, visibly rechecks affected Claims and decisions, and automatically searches for replacement evidence
- (decision) Disabling a Source never mutates completed approved Projects; affected Projects normally show a now-disabled Source warning. Account Settings may hide this warning, but suppression does not change provenance, approvals, Project history, or the exported Source Record
- (decision) Account Settings provides category-specific phone-notification controls for research, generation, validation, Export, and later printing events; essential in-app Project event history remains accessible even when phone alerts are disabled
- (decision) Voice defaults to short ordinary-language explanations with technical terms explained when necessary; Account Settings can switch to a more technical detail level without changing evidence, decisions, or available actions
- (decision) First-version accessibility targets WCAG 2.2 AA and includes complete keyboard operation, screen-reader semantics and announcements, text enlargement, sufficient contrast, visible focus, non-colour status cues, and reduced-motion support on desktop, laptop, and phone
- (change) Direct image-derived picture-to-model conversion must work offline on supported desktop, laptop, and phone devices; research-assisted picture reconstruction remains online-only. Architecture must ratify the on-device feasibility, performance, storage, and fallback contract before implementation
- (decision) An offline-created image-derived model saves locally and remains usable on that device, shows pending and failed sync states, and automatically syncs into the Account My Projects when connectivity returns without duplicating the Project or overwriting a newer Version
- (decision) On phone, picture intake offers both choosing an existing image and taking a new photo; camera permission is requested contextually only after the user selects Take photo
- (decision) One picture-based Project can accept multiple images of the same subject from different angles; all images remain grouped as one model request with add, preview, replace, reorder, and remove controls before confirmation
- (decision) Before picture conversion, nova3D checks image clarity and angle coverage, explains detected problems in ordinary language, and identifies additional views that would improve the requested model
- (decision) Incomplete picture coverage does not permanently block direct conversion: nova3D recommends missing views but offers Generate anyway after explicit warning that uncertain geometry may be invented or inaccurate and remains image-derived, not historically verified
- (decision) Claude Design handoff requests mockups for the complete first-version application, not only the dashboard: authentication, Account and Administrator surfaces, Create paths, research and approvals, In Progress, 3D inspection, correction and Versions, validation and Export, Settings, responsive phone and computer states, and accessibility states
